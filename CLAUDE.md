# Правила работы с проектом Personal German Coach

## Архитектура

- Весь интерфейс — в одном файле `DEMO.html`. Никаких отдельных страниц, никаких фреймворков.
- Никаких внешних библиотек (без Bootstrap, jQuery, Tailwind и т.д.). Только чистый HTML + CSS + vanilla JS.
- Иконки — только текст, символы Unicode или эмодзи. Никаких иконочных шрифтов и SVG-спрайтов.

## Дизайн

### Цвета — не менять без причины
```
Фон:          #FAF9F6  тёплый кремовый
Сайдбар/нав:  #2D3748  тёмный сланец
Акцент осн:   #4A8C6E  шалфей (кнопки, активные элементы)
Акцент светл: #EDF7F1  бледно-зелёный (фон карточек успеха)
Подчёркиван:  #7CC8A0  яркий зелёный (прогресс, иконки успеха)
Срочность:    #D97706  янтарь (входящие, дедлайны)
Текст осн:    #1A1A1A
Текст мутн:   #718096  (мета, подписи)
Граница:      #E2E8F0
```

### Шрифт
`'Segoe UI', system-ui, sans-serif` — только системный, без загрузки.

### Адаптивность — обязательно
- Все новые блоки должны хорошо выглядеть на экране шириной от 375px (iPhone SE).
- Сетки через `grid` с `repeat(auto-fit, minmax(..., 1fr))` — они сами складываются на мобильных.
- Боковые панели (sidebar) на мобильных скрываются (`display:none`), контент занимает всю ширину.
- Кнопки и нажимаемые элементы — минимум 44px в высоту (стандарт пальца).
- Проверять адаптивность перед каждым коммитом: сузить браузер до ~375px и посмотреть.

## Тон и язык интерфейса

- **Простой и дружеский** — как говорит живой человек, не инструкция к прибору.
- Без канцелярита: не "осуществить загрузку", а "загрузить"; не "произвести отправку", а "отправить".
- Студент — на "вы" (уважительно, но тепло). Пример: "Ваше задание на сегодня", а не "Задание пользователя".
- Ошибки и подсказки — поддерживающе, не обвинительно. "Почти правильно — вот как точнее" вместо "Неверно".
- Прогресс — словами, не цифрами на главном экране. "Стало заметно лучше" вместо "72%".

## Процесс работы

### Перед созданием или изменением чего-либо — сначала рассказать
Прежде чем писать код или создавать файл, кратко объяснить:
- что именно планируется сделать
- почему именно так
- какие файлы будут затронуты

Только после подтверждения — приступать.

### Коммиты
- Коммитить только по явной просьбе ("сделай коммит", "запушь").
- Сообщение коммита — на английском, кратко описывает суть изменений.
- Не коммитить `.claude/` папку.

### Новые файлы
- Создавать новые файлы только если без них реально не обойтись.
- Предпочитать редактирование существующих файлов созданию новых.
- Документацию (`.md`) создавать только по явной просьбе.

## Ключевые принципы продукта (не нарушать)

1. **AI — только черновик.** Студент никогда не видит сырой AI-ответ. Всё проходит через преподавателя.
2. **Студент видит минимум.** Одно задание на экране. Никакой перегрузки информацией.
3. **Подсказки — по запросу.** Не показывать сразу, только если студент нажал.
4. **Прогресс — поддерживающий.** Win-баннер появляется когда преподаватель отметил улучшение — не автоматически.
5. **Фидбек — аккордеон.** Не висит на главном экране, студент разворачивает сам когда готов.
