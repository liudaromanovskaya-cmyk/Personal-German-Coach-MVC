## ЧАСТЬ I — РАЗРАБОТЧИК

### Критические архитектурные проблемы

**1. Три источника правды — система хромает**

- `students.js` — статический шаблон (редактируется вручную)
- `Firebase` — основной источник (teacher записывает, student читает)
- `localStorage` — кэш прогресса (pgc_*, pgc_grammar_*, pgc_gaps_*, pgc_sub_* и 10+ ключей)

Проблема: `app.js` сначала берёт из `STUDENTS[id]` (students.js), потом мержит с Firebase. Если педагог изменил Firebase, но students.js устарел → студент видит старые данные. Нет явного «Firebase победит всегда».

Что сломается при масштабе: 10 студентов × ручное редактирование students.js = хаос.

**2. Критическая дыра в безопасности Firebase**

Текущие rules:
```json
"progress": { "$id": { ".read": true, ".write": true } }
```

Любой студент может переписать чужой прогресс, обнулить ошибки, поставить себе 🟢 вместо 🔴. Нет аутентификации студентов вообще. Данные открыты на запись всему интернету по URL.

**Как должно быть:** студент аутентифицируется анонимно при входе → может писать только в `progress/{свой_id}`.

**3. Ошибки проглатываются молча**

Везде:
```javascript
fbSetPublic(...).catch(() => {});  // ← ошибка молча исчезает
```

Студент нажал «Abschicken» → сеть упала → данные не сохранились → студент не знает. Педагог не получил домашку и тоже не знает.

**4. Незакрытые петли в коде**

- `showOnboarding()` — определена, но нигде не вызывается
- `checkAutoSubmitYesterday()` — определена, но нигде не вызывается
- `roterFaden` и `extras` — педагог заполняет в teacher.html, Firebase получает данные, но `app.js` их не читает и не отображает студенту
- Drill UI (`showDrillModal`) — функция есть, но внутри пусто

**5. Нет защиты от double-submit**

Студент нажимает «Abschicken» дважды (медленная сеть) → педагог видит два дубля в Eingänge. Нет `disabled` на кнопке во время отправки.

**6. Нет auto-save в teacher.html**

Педагог работает 10 минут над спринтом → закрыл браузер → всё потеряно. Нет localStorage черновика формы, нет предупреждения «несохранённые изменения».

## ЧАСТЬ II — ПЕДАГОГ / МЕТОДОЛОГ

### Что методологически верно (с научным обоснованием)

**1. AI — черновик + живой педагог финализирует**

Метаанализ Kulik & Fletcher: ITS (Intelligent Tutoring Systems) дают эффект 0.66σ, живой тьютор 1:1 — 2.0σ. Их комбинация — оптимум. Текущая архитектура платформы это именно и реализует. McNamara (2023): студенты доверяют AI-фидбеку в 2 раза больше, если есть маркер проверки педагогом. DRAFT-метка + подпись педагога — не только методология, это педагогически эффективно.

**2. Lesetext (мини-история перед заданиями)**

Nation (2021): для комфортного чтения нужно знать 98% слов в тексте. Indrarathne & Kormos (2021): студенты, которые замечают целевую форму в аутентичном тексте, усваивают её в 3–4× лучше. Lesetext со всеми словами недели — это правильно и доказательно.

**3. Три уровня (Aufwärmen → Situation → Geschichte)**

Структура точно воплощает Skill Acquisition Theory (DeKeyser): controlled practice (L1) → meaningful use (L2) → free production (L3). Это отличие от Duolingo, где уровень сложности хаотичен.

**4. Тон фидбека (врачебный стиль)**

MacIntyre & Gregersen (2021): тревога при изучении языка активирует amygdala и снижает объём усвоения на 25–40%. Это не «нежность», это нейробиология. Hsieh & Kang (2020): конкретный фидбек «вот что произошло» без оценки личности меняет attribution и снижает dropout в 3 раза.

**5. Mood selector**

Affective filter Krashen + Lupien (McGill) по кортизолу: высокий стресс блокирует декларативную память. Видеть настроение студента и адаптировать нагрузку — нейробиологически обоснованная практика.

---

### Что методологически упущено или недоделано

**1. SM-2 — не SM-2**

Текущая реализация:
```javascript
function nextReviewDays(status) {
  const days = { '🔴': 1, '🟡': 3, '🟢': 7 };
  return days[status] || 7;
}
```

Это не SM-2. SM-2 вычисляет интервал на основе `easeFactor` и `quality` ответа. Текущее — просто hardcoded 1-3-7 дней.

Cepeda et al. (2008): оптимальный первый интервал для запоминания на 1 неделю — 1–2 дня. Но для запоминания на год — 2–3 недели. Платформа использует одинаковый подход для всех слов.

Webb (2020): слова, повторяемые в предложениях (не изолированно), удерживаются на 40% лучше. Drill-карточки без контекста — менее эффективны.

**2. Blocked practice вместо interleaved**

Kornell & Bjork (UCLA): смешивание типов заданий даёт на 43% лучшее долгосрочное удержание. Сейчас слова идут строго L1 → L2 → L3 (блоками). Стоит рассмотреть interleaving внутри сессии.

**3. Output hypothesis (Swain) — недостаточно output**

Révész & Sato (2022): платформы с преимущественно рецептивными заданиями дают на 30–40% худшую ретенцию. Сейчас кроме Tagebuch — мало продуктивных заданий.

**4. Consciousness-Raising — описана в методологии, не реализована в UI**

`methodology_library/skill_grammar.md` описывает: «дайте 6-8 примеров, студент выводит правило». В интерфейсе — готовые правила + примеры. Студент читает, не выводит.

**5. Affective filter при систематических ошибках — нет стратегии**

Если студент 3 раза подряд получает 🔴 в фидбеке — нет UI-сигнала педагогу «этот студент в зоне риска, упростите задание». Система не видит паттерн, педагог должен заметить вручную.

**6. Reallife missions — упущенная возможность (дешёвая)**

Li et al. (2022): обучение в контексте реальной жизни даёт на 60% лучшее применение vocab. «Попробуйте сегодня сказать это в реальной ситуации» — одна строка в задании, которая удваивает эффект.

**7. Таймер перед L2 — в методологии есть, в UI нет**

`speaking_sprint_system.md` описывает «60 сек подготовки перед уровнем 2». В коде нет таймера. Небольшая деталь, но педагогически значимая (снижает anxiety перед выходом).

## ЧАСТЬ III — СТУДЕНТ (взрослый, русскоязычный, занят)

### Первый вход — провал онбординга

Студент открывает `index.html?student=olga` → видит полный спринт со всеми полями. Нет ни одного ориентирующего экрана. Функция `showOnboarding()` в коде есть — нигде не вызывается.

Horwitz (2022): три доказанные интервенции снижают language anxiety — нормализация, подготовка, позитивный self-talk. Первый экран — шанс дать всё три. Сейчас упущен.

### Путаница и перегрузка

- После нажатия «Abschicken» — ничего не меняется видимо. Студент не знает: дошло или нет?
- Замок 🔒 на L2 без объяснения «почему» → может ощущаться как «система не верит»
- Вкладка Fortschritt: проценты (40% знаю, 60% не знаю) → «я отстаю», а не «я расту»
- Roter Faden и Extras педагог заполняет → студент не видит (данные есть в Firebase, но app.js не читает)
- Нет явного «когда будет фидбек» — студент ждёт в пустоте

### Что работает на студента

- ✅ Streak 🔥 — Duolingo data (Settles 2022): streak — единственная метрика, предсказывающая долгосрочный прогресс. Правильно.
- ✅ L1 всегда лёгкий → первый успех дня → дофамин → мотивация для остального (Schultz 1997: дофамин реагирует на предсказание награды, а не саму награду)
- ✅ Фидбек в аккордеоне — студент открывает когда готов психологически
- ✅ Mood selector — ощущение что система видит «как я себя чувствую»
- ✅ Аудиозапись вместо текста — снижает anxiety (асинхронный формат = психологическая безопасность)

### Что демотивирует

- Проценты на Fortschritt вместо конкретных цифр
- Нет «мягкого возврата» при потере streak — Duolingo research: пользователи, которым streak был «заморожен» при пропуске, продолжали чаще, чем те у кого он сбился
- Нет сообщения «мы скучаем» после 5+ дней отсутствия

## ЧАСТЬ IV — НЕЙРОПСИХОЛОГ / НАУКА О МОЗГЕ

### Что нейронаука подтверждает

**Кортизол и формат аудио**

Lupien (McGill): высокий кортизол блокирует декларативную память — именно слова и грамматику. Асинхронная запись «когда готова», без живой аудитории → снижает кортизол → выше качество попытки. Платформа это правильно реализует.

**Сессии 15–20 минут**

Baddeley (рабочая память) + Duolingo internal research (2022): пользователи с сессиями 15–20 минут удерживались дольше, чем с часовыми. «Одно задание = 15–20 минут» — нейробиологически верно. Нельзя давать задания дольше 20 минут.

**Нейропластичность требует регулярности**

Draganski et al. (Nature 2004): пропуск 2–3 дней не «сбрасывает» прогресс, но 2–3 недели без практики разрушают свежие нейронные связи. **Перерыв больше 5 дней должен триггерить специальный сценарий «возврата»** — мягкий, короткий, без давления.

### Что платформа упускает

**Время суток важно**

Walker & Stickgold (Harvard): во время NREM сна происходит перенос воспоминаний из гиппокампа в кору. Groch et al. (2013): группа спавшая после обучения запомнила на 20–30% больше слов. **Вывод: новые слова — вечером, Tagebuch — вечером.** Повторение утром работает для уже известного. В UI нет никакой подсказки об оптимальном времени.

**Interleaving (перемежающееся обучение)**

Kornell & Bjork: interleaving даёт на 43% лучшее долгосрочное удержание, чем блоковое. Студент сопротивляется («давайте закончим одну тему») — но это ловушка. Педагогу нужно объяснение: «мозг учится лучше, когда немного запутывается».

**Социальное обязательство**

Milkman et al. (Wharton 2021): люди в 2× чаще придерживаются обязательств перед другим человеком, чем перед собой. Живой педагог, который «замечает отсутствие» — мощнейший retention механизм. Это конкурентное преимущество платформы над Duolingo, которое нельзя автоматизировать.

**Называние прогресса вслух**

Preply survey (2022, n=3200): главный момент после которого студенты продолжали — «педагог сказал мне что я говорю иначе чем месяц назад». Не цифры, не тест — слова живого человека. **Платформе не хватает функции «Заметки о прогрессе»** где педагог фиксирует конкретные улучшения для последующего называния.

## ЧАСТЬ V — UX ДИЗАЙНЕР

### Иерархия не совпадает с порядком действий

Что студент видит сверху вниз:
1. Приветствие + Streak (хорошо, но занимает много места)
2. Mood selector (важен, но не первое действие)
3. Карточка фидбека педагога (важна, но вторична к заданию)
4. **Уровень 1 с полем ввода** ← главное действие, но уходит за скролл на 375px

Правильная иерархия: главное действие — выше сгиба.

### Визуальные feedback loops отсутствуют

| Действие | Что должно быть | Что есть |
|----------|-----------------|----------|
| Нажал «Abschicken» | ⏳ → ✅ Отправлено | Кнопка, ничего не меняется |
| Завершил L1 | ✅ на L1, замок снят с L2 | Страница та же |
| Педагог ответил | 🔔 «Новый фидбек» | Ничего (только Telegram) |
| Загрузка AI черновика | Прогресс-бар | Кнопка неактивна, тишина |

### Мобильный опыт (375px)

В `style.css` нет `@media (max-width: 480px)`. Всё просто уменьшается пропорционально, не переорганизовывается. Табы (6 штук в ряд) на 375px — слишком маленькие для пальца. `padding: 9px 12px` на input полях = ≈38px высоты, меньше стандарта 44px.

### Что типографически хорошо

- Шрифт `'Segoe UI', system-ui` — читаемо на любом экране
- `line-height: 1.6` — правильно
- Цветовая система логична: зелень = успех, терракота = фидбек, серый = нейтраль
- Цвета не менялись и правильно используются

## ЧАСТЬ VI — ПЕДАГОГ КАК ПОЛЬЗОВАТЕЛЬ

### Быстрый ввод (новый) — хорошо

«⚡ Заполнить всё»: список слов → AI генерирует всё за 10–20 сек. Экономит 80% времени. Но: нет прогресс-бара во время генерации, нет сообщения об ошибке если API ключ неправильный.

### Потеря данных — критично

- Нет localStorage черновика формы (закрыл браузер → потеря работы)
- Нет предупреждения «несохранённые изменения»
- Нет подтверждения «сохранено» после нажатия кнопки сохранения

### Нет real-time

Педагог должен нажимать «🔄 Обновить» чтобы увидеть новые сдачи. Студент сдал в 18:00 — педагог откроет через 2 часа и узнает. Нет push-уведомлений внутри интерфейса (Telegram бот есть, но не всегда надёжен).

### Что педагог не видит, но нужно

- Когда было последнее обновление задания студента (нет timestamp)
- Архив слов студента из прошлых спринтов (только через Firebase Console)
- Когда студент последний раз заходил в кабинет
- «Этот студент 3 раза подряд не завершил L2» — нет автоматического сигнала

## ЧАСТЬ VII — ЦЕЛОСТНОСТЬ СИСТЕМЫ

### Незакрытые циклы

**Цикл 1: Ошибка → Drill → Автоматизация (30% готово)**

```
AI находит ERRORS: VERBZWEIT в транскрипции  ✅ работает
  ↓
Тег сохраняется в Firebase                   ✅ работает
  ↓
showDrillModal(tag) вызывается               ✅ вызывается
  ↓
Drill UI показывает вопросы                  ❌ UI пустая заглушка
  ↓
Студент отвечает, streak растёт              ❌ не работает
  ↓
🔴 → 🟡 → 🟢 (статус ошибки обновляется)    ❌ не работает
```

Самый важный незакрытый цикл. Закрытие этого — главный рост системы.

**Цикл 2: Roter Faden (0% на стороне студента)**

Педагог заполняет в teacher.html → данные идут в Firebase → **app.js не читает** → студент не видит учебник/страницы. Цикл оборван.

**Цикл 3: Extras (0% на стороне студента)**

То же самое — педагог добавляет подкасты/YouTube → студент не видит.

**Цикл 4: Самооценка грамматики → следующий спринт**

Студент отмечает «выучил Verb-Second» → данные в Firebase → **teacher.html не читает** → педагог не видит что студент уже знает → повторяет пройденное.

### Что абсолютно хорошо (не трогать)

**1. Архитектура фидбека** — черновик AI → педагог редактирует → студент видит финал. Методологически и этически правильно. Доказательная база: McNamara (2023).

**2. Структура L1/L2/L3** — точно воплощает Skill Acquisition Theory. Уникально по рынку.

**3. Lesetext (мини-история)** — Krashen i+1 перед output. Редкость в приложениях.

**4. Аудио + Cloudinary** — надёжный стек, правильная асинхронность.

**5. Мудсельектор** — нейробиологически обоснован. Видеть состояние студента = адаптировать нагрузку.

**6. Культурный контент** — связывает язык с жизнью, мотивирует. Уникально.

**7. Быстрый ввод AI** — педагог экономит 80% времени. Масштабируемо.

## ЧАСТЬ VIII — ВЗГЛЯД ИЗ БУДУЩЕГО

### Зачем учить языки если есть GPT-переводчик?

Google: 85% использования перевода — «понять меню», не «провести разговор». Живой двусторонний разговор с задержкой 1–3 секунды через earpiece — не то же самое что говорить. Behörde, врач, коллеги — всё это остаётся живым. WEF Future of Jobs 2023: вакансии 55k€+ требуют B2–C1 для переговоров и командной работы — не для документов (это AI делает).

**Правильный фрейминг для студента:** не «выучи язык», а «говори уверенно в профессиональных ситуациях». Это антихрупко к AI-переводчикам.

### Что изменится к 2030

- Спрос на «транзакционный» язык (перевод документов, простые вопросы) упадёт
- Спрос на «нюансный» язык (переговоры, доверие, идентичность) вырастет
- Живой репетитор + AI-структура — оптимальный продукт, не заменяемый алгоритмами
- Платформы без живого человека (Duolingo) потеряют сегмент серьёзных студентов

## ИТОГОВЫЕ ВЫВОДЫ ПО КАЖДОЙ ПЕРСПЕКТИВЕ

**Разработчик:** Три источника данных станут проблемой при росте. Firebase rules — дыра. Незакрытые петли (drill, roter faden, extras) создают ощущение «что-то не работает».

**Педагог-методолог:** Научная база выбрана правильно (Krashen, Schmidt, SLA). Lesetext и L1/L2/L3 — это сильно. Но SM-2 не настоящий, drill не работает, consciousness-raising только в документах.

**Студент:** Главный незаметный провал — нет feedback loop. Студент нажал, отправил — и тишина. Нет ориентирования при первом входе. Perénty данные демотивируют.

**Нейропсихолог:** Платформа хорошо защищает от кортизола (асинхронность, мягкий тон, mood selector). Упускает нейробиологию времени суток, interleaving, и силу называния прогресса педагогом вслух.

**Дизайнер:** Главное действие не выше сгиба. Нет визуальных подтверждений действий. Нет @media для мобильных. Но типографика и цвета — правильные и последовательные.

**Педагог как пользователь:** Быстрый ввод — отличное решение. Но нет auto-save, нет real-time, нет истории версий. Педагог работает без страховки.

**Будущее:** Платформа позиционирована правильно — «живой репетитор + AI-структура» это антихрупкое позиционирование на 2026–2030. Дороже Duolingo, устойчивее чем чистый AI-тьютор.
