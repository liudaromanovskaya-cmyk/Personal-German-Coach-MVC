## ПРИОРИТЕТ 1 — КРИТИЧЕСКИЕ ДЫРЫ (делать первыми)

### 1.1 Два источника истины → один
**Проблема:** `students.js` в коде И Firebase в teacher.html — непонятно где "настоящие" данные.
**Решение:** Всё в Firebase. students.js — только дефолты для новых студентов. Живые данные всегда из Firebase.
**Риск без исправления:** педагог меняет задание в teacher.html, но students.js перезаписывает при деплое.

### 1.2 localStorage → Firebase для прогресса студента
**Проблема:** Прогресс (отмеченные критерии, статусы слов) хранится в localStorage. Студент открывает с другого устройства — прогресс пропал.
**Решение:** Все студенческие действия (чекбоксы, оценки слов, настроение) сохранять в `progress/{studentId}/` в Firebase в реальном времени.
**Риск без исправления:** при 10+ студентах начнут жаловаться на потерю данных.

### 1.3 Dashboard для педагога
**Проблема:** Нет никакой аналитики. Педагог не видит: сколько дней занимается студент, какой процент заданий выполняет, в какие дни активен, тренд ошибок.
**Решение:** Раздел "📊 Статистика" в teacher.html:
- Дней активности за месяц
- % выполненных заданий
- Топ повторяющихся ошибок (из архива фидбека)
- График активности по дням недели

### 1.4 Версионирование плана
**Проблема:** Педагог изменил слова — старый план пропал навсегда.
**Решение:** При каждом сохранении плана — автоматически создавать снапшот в `archive/{studentId}/{timestamp}`. Кнопка "Восстановить предыдущую версию".

## ПРИОРИТЕТ 2 — ПЕДАГОГИЧЕСКИЕ ПРОВАЛЫ (по науке)

### 2.1 Spaced Repetition — сделать механику, не обещание
**Проблема:** Слова "возвращаются спирально" только если педагог вручную вспомнит. Системы нет.
**Решение:**
- Firebase хранит: слово + дата первого показа + оценки студента по датам
- Алгоритм SM-2 (Anki) автоматически выбирает 3 слова из прошлых спринтов для включения сегодня
- Педагог видит: "Система рекомендует включить: [слово1, слово2, слово3] из спринта 2 недели назад"
- Студент видит бейдж 🔄 и знает: это старое слово на повторение

### 2.2 Input Hypothesis — живой немецкий в кабинете
**Проблема:** Студент видит только текст урока. Ни одного аутентичного немецкого текста или видео. Input Hypothesis (Krashen) полностью провалена.
**Решение (минимально):**
- В разделе "Kultur" добавить: короткий аутентичный текст (новость, цитата, рецепт) уровня i+1
- Выделить в нём слова текущего спринта — студент "замечает" форму в живом контексте
- Ссылка на 1 YouTube-видео или подкаст по теме недели

### 2.3 Noticing Hypothesis — студент замечает форму сам
**Проблема:** Schmidt (1990): усвоение происходит когда учащийся сам замечает форму. Сейчас форму даёт педагог готовой. Noticing отсутствует.
**Решение:**
- В грамматике недели: "Найдите ошибку в этом предложении" (Error Noticing)
- "Попробуйте вывести правило сами по этим примерам" (Consciousness-Raising)
- В фидбеке: не "правильно так", а "а как вы думаете, почему немец скажет иначе?"

### 2.4 Микро-упражнения из методики — встроить в кабинет
**Проблема:** В methodology_library есть: shadowing, picture description, opinion drill, retelling, text rebuilding. Студент их не видит — они лежат мёртвым грузом.
**Решение:** Добавить в задания дня (по ротации):
- **Shadowing** (уровень 0 перед Niveau 1): "Повторите за мной фразу немца"
- **Error Correction Awareness**: "Здесь 3 ошибки — найдите их"
- **Retelling**: "Перескажите своими словами что прочитали"

### 2.5 Грамматика — из карточки в практику
**Проблема:** "Грамматика недели" = карточка с правилом. Нет интерактива, нет задания, нет проверки.
**Решение:** К каждой грамматической теме добавить:
- 3 предложения с пропусками (заполнить правильную форму)
- 1 предложение с ошибкой (найти и исправить)
- Студент отправляет → педагог видит в Eingänge

### 2.6 Аффективный фильтр — мудсельектор с действием
**Проблема:** Krashen (1982): тревожность блокирует усвоение. Мудсельектор спрашивает как студент себя чувствует, но ничего не делает с ответом.
**Решение:**
- 😰 "Устала" → показывать технику "3-2-1 Before Speaking" + только Niveau 1 + ободряющее сообщение от педагога
- 😊 "Отлично" → открывать бонусный уровень или сложный вариант задания
- Педагог видит в teacher.html: какое настроение студент выбирал последние 7 дней

## ПРИОРИТЕТ 3 — UX И МОТИВАЦИЯ (для удержания)

### 3.1 Убрать бомбардировку на главном экране
**Проблема:** Студент видит одновременно: фидбек-карточка + review + grammar-блок + mode-switcher + три уровня. Паралич выбора.
**Решение:** Последовательный интерфейс:
- Первый экран: ТОЛЬКО фидбек (если есть) + одна большая кнопка "Начать задание"
- После нажатия: Niveau 1 → выполнил → Niveau 2 открывается → и т.д.
- Прогресс виден как шаги, а не как список

### 3.2 Аудио-архив с прогрессом
**Проблема:** Записи студента накапливаются в Cloudinary, но нигде не показываются. Самый мощный инструмент мотивации не используется.
**Решение:** Вкладка Fortschritt → раздел "Meine Reise":
- Временная шкала: февраль → март → апрель
- Студент нажимает на дату → слышит свою запись
- Педагог выбирает "запись февраля" и "запись апреля" → отправляет milestone карточку: "Слышите разницу?"

### 3.3 Серия дней и микро-победы
**Проблема:** Нет streak (серии дней), нет ощущения накопления. Студент не видит своей последовательности.
**Решение:**
- Счётчик дней подряд (🔥 7 Tage in Folge) — уже есть в Tagebuch, нужно вынести на главный экран
- При серии 7 дней → специальная карточка "Вы занимались неделю подряд"
- При 30 днях → педагог получает уведомление → отправляет личное поздравление

### 3.4 Фридбек-петля за 24 часа
**Проблема:** Студент ждёт фидбек 5–24 часа. SLA требует сжатый цикл.
**Решение:** Договоренность: педагог отвечает до вечера того же дня. Система показывает студенту: "Лиуда прочитает вашу работу сегодня до 20:00". Снимает тревогу ожидания.

## ПРИОРИТЕТ 4 — МАСШТАБИРОВАНИЕ (для 10+ студентов)

### 4.1 Сокращение времени педагога: цель 20 мин/день на студента
**Проблема:** Сейчас 1.5–2.5 часа при 5 студентах. При 10 студентах — 3–5 часов. Неприемлемо.
**Решение по шагам:**
- **Шаблоны фидбека**: библиотека 20–30 типичных ошибок с готовыми формулировками → 1 клик → вставить
- **Групповые ошибки**: если 3 студента делают одну ошибку → педагог пишет один раз, система рассылает адаптированную версию
- **Авто-приоритизация**: AI автоматически помечает "эта работа требует развёрнутого фидбека" vs "достаточно краткого подтверждения"
- **Голосовой фидбек педагога**: записать войс-сообщение вместо текста → студент слышит живой голос

### 4.2 Telegram Bot как основной канал
**Проблема:** Аудиозапись через браузер = фрикция. В Telegram это нативно.
**Решение:** `/record` в боте → микрофон → сразу в Firebase. Без открытия браузера, без кнопок.

### 4.3 Архитектура данных под рост
**Проблема:** Глобальные переменные в app.js (`_student`, `_firebaseTeacherData` и т.д.) — это тайм-бомба при нескольких педагогах или real-time синхронизации.
**Решение:** Перейти на state-объект с getter/setter. Подготовить к тому что будет 2 педагога или помощник.

## ПРИОРИТЕТ 5 — ДОЛГОСРОЧНОЕ ВИДЕНИЕ (18 месяцев)

### Месяц 1–3: Живой цикл (где мы сейчас)
- ✅ Аудио → Firebase → Eingänge → фидбек → кабинет
- ✅ Архив фидбека
- 🔜 Аудио-архив студента
- 🔜 localStorage → Firebase

### Месяц 4–6: Система учится
- Анализ архива → автоматическая рекомендация грамматики недели
- Слова из фидбека → автоматически в следующий спринт (без ручного переноса)
- Dashboard педагога с трендами

### Месяц 7–12: AI как соавтор
- Фидбек педагога → AI извлекает ошибки → следующий день содержит задание именно на эту ошибку
- AI генерирует полный план недели → педагог только редактирует черновик
- Spaced Repetition автоматический — педагог не думает о повторении слов

### Месяц 13–18: Масштаб
- 1 педагог → 30–50 студентов (без увеличения времени работы)
- AI знает каждого студента: его ошибки, прогресс, психологический профиль
- Педагог = куратор качества, а не производитель контента каждый день
- Персональный лингвистический GPS: студент видит свою карту языка — что освоено, что впереди
